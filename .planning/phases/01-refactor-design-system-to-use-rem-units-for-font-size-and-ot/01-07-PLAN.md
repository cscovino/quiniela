    The current sw.js already has proper cache versioning (CACHE_NAME = 'quiniela-v4') with install/activate lifecycle that deletes old caches. The pattern is correct — it just needs a version bump on each deploy.

    Two improvements:
    1. Bump CACHE_NAME from 'quiniela-v4' to 'quiniela-v5' to invalidate existing caches after this phase's changes
    2. Add a visible update notification: when a new service worker is found (waiting state), show a toast/notification prompting the user to refresh for the latest version

    For the update notification:
    - In sw.js, add a message listener that sends 'UPDATE_AVAILABLE' message to clients when a new service worker is ready
    - In the app's main entry point (or a new UpdateNotifier component), listen for service worker messages and show a toast when 'UPDATE_AVAILABLE' is received
    - The toast should have a "Refresh" button that calls window.location.reload()

    Add to sw.js (after existing listeners):
    ```javascript
    self.addEventListener('message', (event) => {
      if (event.data === 'SKIP_WAITING') {
        self.skipWaiting();
      }
    });
    ```

    The existing activate listener already calls `self.clients.claim()` which activates the new service worker immediately. Combined with the CACHE_NAME bump, this ensures fresh assets.
  </action>
