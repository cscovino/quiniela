<objective>
Replace all hardcoded tournament name strings in production source code with dynamic values from the i18n translation files.

**Purpose:** Currently, "FIFA World Cup 2026", "WC26", and related strings are hardcoded across source files. When the tournament changes (e.g., World Cup 2030), every occurrence must be found and replaced manually. This phase centralizes the tournament name in translation files so that changing the tournament for a future edition requires only editing the JSON translation files and rebuilding.

**Note on scope:** Strings already stored in translation files (e.g., `site.description` in `common.json` that read "Haz tus predicciones para la Copa Mundial FIFA 2026") are already localized and in the correct mechanism — they happen to contain the tournament name as part of a sentence. These are NOT hardcoded in source code and are out of scope for replacement. This phase targets strings hardcoded directly in `.tsx`, `.astro`, and other source files.

**Out of scope (separate concerns):**
- `scripts/seed-tournament.ts` / `scripts/test-e2e.ts` — these set the Firestore tournament doc `name` field (data seeding, not display)
- CSS variable names (`--gradient-wc26-*`) — these are design token identifiers, not display strings
- Test/mock data strings — test fixtures are intentionally static
- Design token Storybook stories — "WC26" as a design system label is stable
</objective>
