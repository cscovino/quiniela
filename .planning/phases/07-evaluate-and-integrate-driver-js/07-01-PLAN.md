<objective>
Evaluate and integrate [driver.js](https://driverjs.com/) — a lightweight (~7KB gzipped, zero deps) product tour library — for onboarding new users and highlighting prediction flow features.

**This plan has two phases:**

1. **SPIKE** (Tasks 1–2): Install driver.js on a throwaway branch, prototype a tour through the prediction wizard, evaluate CSP compatibility, bundle size impact, and pixel-art styling feasibility. Results determine whether integration proceeds.

2. **INTEGRATION** (Tasks 3–5, conditional on spike approval): Build a reusable `ProductTour` organism component, define tour steps for the prediction flow and rankings page, style the popover to match the retro pixel-art design system, persist completed tours, add trigger buttons, and document the integration.

**Purpose:** First-time users often don't know about the step-by-step prediction wizard (matches → groups → knockout → best players). A guided tour reduces friction and increases prediction completion rates.
**Output:** Spike evaluation report + (if approved) ProductTour component, styled popover, trigger buttons, persistence layer, and AGENTS.md updates.
</objective>

    ### 1. Define the Type Interface
    Create `src/components/organisms/ProductTour/ProductTour.tsx`:

    ```typescript
    import React, { useEffect, useRef, useCallback } from 'react';
    import { driver, type DriveConfig, type DriveStep } from 'driver.js';
    import 'driver.js/dist/driver.css';  // base styles, overridden by our CSS
    import './ProductTour.css';

    export interface TourStepConfig {
      /** CSS selector for the element to highlight */
      element: string;
      /** Popover title (rendered in Press Start 2P) */
      title: string;
      /** Popover body text */
      description: string;
      /** Optional side for popover positioning: 'left'|'right'|'top'|'bottom' */
      side?: 'left' | 'right' | 'top' | 'bottom';
      /** Optional alignment: 'start'|'center'|'end' */
      align?: 'start' | 'center' | 'end';
      /** Optional step index to disable navigation buttons for this step */
      hideNavigation?: boolean;
      /** Optional step index to show a progress indicator like "2/5" */
      showProgress?: boolean;
    }

    export interface ProductTourProps {
      /** Unique tour identifier for persistence tracking (e.g. 'prediction-wizard') */
      tourId: string;
      /** Ordered array of tour steps */
      steps: TourStepConfig[];
      /** Called when the tour completes (all steps finished) */
      onComplete?: () => void;
      /** Called when the user closes the tour early */
      onClose?: () => void;
      /** Optional class name for the trigger wrapper */
      className?: string;
      /** If true, the tour starts automatically on mount (for first-time flows) */
      autoStart?: boolean;
      /** Storage key prefix for localStorage persistence */
      storagePrefix?: string;
    }
    ```

    ### 2. Implement the Component

    The component should:
    - Accept a `tourId` (e.g. `'prediction-wizard'`, `'rankings-guide'`) for persistence tracking
    - Map `TourStepConfig[]` to `driver.js`'s `DriveStep[]` format internally:
      ```typescript
      const driveSteps: DriveStep[] = steps.map((step) => ({
        element: step.element,
        popover: {
          title: step.title,
          description: step.description,
          side: step.side || 'bottom',
          align: step.align || 'center',
        },
      }));
      ```
    - Create a `driver` instance with `showProgress: true`, `animate: true`, `allowClose: true` and the `popoverClass: 'driver-pixel-popover'` config option
    - Expose `startTour()` and `stopTour()` methods via `useImperativeHandle` OR use a simpler approach: expose a `start` function returned by a `useDriver` internal hook, and trigger it via a ref pattern or by exposing a `start` method imperatively
    - Check localStorage on mount: if `tourId` has been completed (`localStorage.getItem('tour_completed_' + tourId)`), do not auto-start (unless `autoStart` prop overrides)
    - Render nothing visible — the component is a controller, not a visual element. It manages the driver.js lifecycle.
    - Accept `className` prop applied as wrapper class (the wrapper is a `<div>` around the trigger, or use a render-prop pattern if the parent wants to control the trigger)
    - Use `useEffect` cleanup to destroy the driver instance on unmount:

    ```typescript
    const driverRef = useRef<ReturnType<typeof driver> | null>(null);

    const startTour = useCallback(() => {
      if (driverRef.current) {
        driverRef.current.drive();
      }
    }, []);
    ```
