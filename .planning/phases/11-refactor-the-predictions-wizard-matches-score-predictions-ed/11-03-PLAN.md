  <action>
    Per D-05 (CAPTCHA flashing: reCAPTCHA badge appears during auth loading):

    **Root cause:** `initializeAppCheck` in `ensureApp()` eagerly triggers reCAPTCHA v3, which injects the `.grecaptcha-badge` into the DOM immediately when Firebase modules first load (during `getAuthInstance()` or `getDb()`). This happens before `isAuthLoading` transitions to `false`, so the badge appears while the loading spinner is visible.

    **Fix: Defer AppCheck initialization from `ensureApp()` to `getAppCheckToken()`.**

    1. In `firebase.ts` lines 30-36 (the `ensureApp` function):
       Remove the eager `initializeAppCheck` block entirely from `ensureApp()`.

    2. In `getAppCheckToken()` (lines 51+):
       Add AppCheck initialization as a lazy singleton pattern:
       ```typescript
       let appCheckInitialized = false;
       
       export async function getAppCheckToken(): Promise<string | undefined> {
         if (!isAppCheckEnabled) return undefined;
         
         if (!appCheckInitialized) {
           _appCheck = initializeAppCheck(app, {
             provider: new ReCaptchaV3Provider(recaptchaKey),
             isTokenAutoRefreshEnabled: true,
           });
           appCheckInitialized = true;
         }
         
         try {
           const token = await getToken(_appCheck!);
           return token.token;
         } catch {
           return undefined;
         }
       }
       ```
       
       Where `isAppCheckEnabled` is derived from `recaptchaKey && import.meta.env.PROD` at module scope (extract from the current ensureApp condition).

    3. **Import check:** Ensure `initializeAppCheck, getToken, ReCaptchaV3Provider` are imported (they likely are from lines 3-4 of firebase.ts).

    **What this achieves:** The reCAPTCHA badge is NOT injected into the DOM until the first call to `getAppCheckToken()`. Since the prediction wizard (and all client-side code) doesn't call `getAppCheckToken()` at all (it's currently unused), the badge won't appear during auth loading. If future code needs AppCheck tokens, the badge will appear on first token request — a predictable, non-flashing behavior.

    **No changes needed to** `auth-store.ts` — `isAuthLoading` lifecycle (init=true, onAuthStateChanged sets false) is already correct.
